master ループを **1 周だけ** 実行する。`/loop` が本コマンドを反復して呼ぶ。

あなたは**判定役**である。実装しない。コードを書き換えない。
自分が書いたものを自分で通すと、ゲートは形だけになる。

## 絶対ルール

> **`bin/loop-gate <PR番号>` が終了コード 0 を返さない限り、理由を問わず
> `gh pr merge` を実行してはならない。判断でゲートを迂回しない。**

> **`@codex review` は `bin/loop-review-budget <PR番号>` が 0 を返したときだけ投げる。**
> これを破ると、レビューが止まらずトークンを溶かす。過去に 40 往復した実績がある。

`main` へ直接 push しない。`git commit` / `git push` / ファイル編集をしない。

## 1. 停止条件

`loop/STOP` が存在するなら、**何もせず直ちに停止する。**

### 1.0 同じ役の周回が走っていないか確かめる

**通知で始めた周回と、cron の周回が重なりうる。** 重なると、両方が
`bin/loop-review-budget` で「まだ要求していない」を読み、**レビュー要求を 2 件とも
投稿する**（判定と投稿は別の操作で、間にロックが無い）。**枠を一度に使い切る**うえ、
症状は「上限に達した」なので**原因が競合だと分からない**。

**冒頭で決着させる。** ゲートを回してから気づく形にしない。

```bash
bin/loop-lease acquire master "<この手順書の冒頭にある `版:` の値>"   # token を控える
```

- **exit 0** → 続ける。**この周回を終えるとき（何もせず終わる場合も含めて）必ず返す**

  ```bash
  bin/loop-lease release master "<token>"
  ```

- **exit 1** → 走っている周回がある。**何もせず終わる。**
  **待たない。** 走っている側が同じ状態を読むので、待っても同じ結論にしかならない。
  既に読み終えた後だった場合は 1 拍落ちるが、**次の周回（保険）が拾う**
- **exit 2** → 設定か環境の誤り。標準エラーに出た内容を報告して終わる

**印がずれていたら、`acquire` は exit 3 で止まる** (#241 / #243 / #244 のレビュー)。
**exit 2（設定か環境の誤り）とは行き先が違う**ので、**番号で分ける**——
**文言で見分けない。**
**配られた手順書がディスクより古い**ということなので、**この周回は捨てて呼び直す**
（**1 回だけ**。**lease は取れていないので返さない**）。

**ここで `bin/loop-stall --reset` を呼ばない。** **消すと、次の周回が積んだぶんも
一緒に消える**——**毎周回 1 に戻り、3 周へ永久に届かない**（**古い版が配られ続ける
障害で、誰も呼ばれない**）。**1.1 の `--reset` は「HEAD が動いた」＝前へ進んだ証拠が
あるとき**のもので、**こちらは印がずれただけで何も動いていない。**

**呼び直しでも同じ印なら、ディスクから読み直す** (#373)——**届く保証は無い**（#94）。

```bash
bin/loop-procedure-body --entry master   # これがこの周回の入口である
bin/loop-lease acquire master "<読み直した入口の `版:` の値>"   # 印は捨てない
```

**呼び直しても同じなら、そこで終える**——**`bin/loop-stall procedure-stale` を通す**。
**積むのは 2 回目だけ**（**1 回目でも積むと、1 件の配り間違いが 2 つ数えられる**）。
**3 周続けば `loop/STOP` が配られ、人が来る。**

**取れなかったことを黙って飲み込まない。** 何周も取れないなら、
**返し忘れた周回がある**（期限が切れれば自動で引き継がれるが、それまで動かない）。

存在しない場合、自分が worktree 側（`~/valence-master`）にいることを確認する。
`git rev-parse --show-toplevel` が `~/valence` を指すなら、worker の作業ツリーにいる。
`bin/loop-stall wrong-worktree` を通して停止する。

### 1.1 手順とスクリプトを最新にする

**master は checkout しない設計なので、`./task loop:setup` で作った時点の commit に
貼り付いたままになる。** worker と違い、ここで追随しないと**マージした改善が master 自身に
届かない**。手順書もスクリプトも古い版を実行し続ける。

実際に踏んだ。2 コミット遅れたまま周回しており、**「一覧に無い停止識別子を弾く」検査が
master 側だけ無効**だった。古い手順でも一見正常に動くのでエラーにならず、
worktree の commit を人が見るまで気づけなかった。

```bash
before="$(git rev-parse HEAD)"
bin/loop-sync-main          # 移った先の SHA を出す（before と比べる）
```

**やり直すかどうかは、回数ではなく理由で決まる** (#217)。**判断はスクリプトが持つ**
ので、ここに条件を書き写さない（**worker も同じものを通る**）——**やり直してよい理由の
一覧は増える**ので、**写した側だけが古くなる。** **性質だけ覚えておけばよい**——
**一時的なもの（もう一度投げれば通る）はやり直し、恒久的なものはやり直さない。
知らない理由は止まる側**である。

失敗したら `bin/loop-stall main-sync-failed` を通して停止する。
**古い手順で走り続けるより止まるほうがよい。**

```bash
bin/loop-procedure-changed --role master "$before"
```

**対象の一覧はスクリプトが持つ**（`--list` で見られる）。**ここに書き写さない** ——
2 箇所に持つと、ファイルが増えたときに片方だけ直して食い違う。

**`exit 1` だけが「続けてよい」。それ以外はすべて捨てる。**

| 終了コード | 扱い |
| --- | --- |
| 1 | 変わっていない。そのままステップ 2 へ進む |
| **1 以外**（0・2 のほか、**126 / 127 や未知の値も**） | **入れ替わった扱い。この周回はここで終わり** |

**`exit 2` だけを並べない。** 並べると**並べ忘れた値が抜ける**。判定器そのものが
消えた・実行できない（**126 / 127**）ときは**どの分岐にも入らず**、
**「判定不能なら捨てる」が成立しなくなる**（実際に踏んだ）。
**古い手順で走り続けるより止まるほうがよい**、が元の判断である。

```bash
bin/loop-stall --reset main-sync-failed   # 打ち切る場合だけ。終える前に必ず通す
```

**`--reset` が落ちても、周回は止めない** (#270)。**前へ進んだあとに止めると、
進んでいるのに 3 周で全ループが止まる。** **落ちる道は実在する**——**ロックを取れない**
（もう一方のループが書いている最中）、**設定の誤り**、**2 引数を知らない版がディスクにある**
（実際に踏んだ）。**標準エラーに出た内容を報告して、そのまま先へ進む**——
**言うことと、止めることは別**である。**消えなかったカウンタは、次の周回が同じ状態を
見れば足りる。**

**消すのは、同期の失敗のぶんだけ** (#266)。**前へ進んだ証拠は「HEAD が動いた」＝同期が
成功したこと**なので、**消せるのもそのぶんだけ**である——**全部消すと、呼び直した先が
印ずれで積んだぶんまで次の周回が消し**、**同じ障害が何周続いても人が呼ばれない**。

**終える前にカウンタを消す。** ここはステップ 7 を通らずに周回を終える唯一の経路で、
消し忘れると「同期に 2 回失敗 → 成功して HEAD が動く → もう 1 回失敗」で
**成功した周回を挟んでいるのに 3 周連続と数え、全ループを止める**。
HEAD が動いたことは前へ進んだ証拠なので、ここで数え直す。

**打ち切ったら、その場で `/loop-master` を呼び直す。** 次の cron まで待つと、
その間は**両方のループが完全に空く**ので、呼び直すほうがよい。

**ただし、新しい版が読み込まれる保証は無い**（実測で 2 回中 1 回。#94）——**理由は本体の付録**。

**呼び直す前に、カウンタを消して lease を返す。**

```bash
bin/loop-stall --reset main-sync-failed
bin/loop-lease release master "<token>"
# ここで /loop-master を呼び直す
```

**握ったまま呼び直すと、呼び直された周回が 1.0 で自分自身に阻まれる**
（`acquire` が exit 1 → 何もせず終わる）。**結局、次の cron まで動かない。**

**返してから呼び直すまでの隙間に cron の周回が入ってよい。** そちらが同じ状態を読んで
同じ仕事をするだけである（1.0 の「待たない」と同じ理由）。

**呼び直しは 1 回だけ。** 呼び直した先で再び打ち切りになったら、**そこで終える**。
入れ替わりは**追随した時点で収束する**ので、2 回続けて起きるのは異常である。
**繰り返す形にしない。**

### 1.2 本体をディスクから読む

**この手順書は入口である。** **ステップ 2 以降はここには無い。**

```bash
bin/loop-procedure-body master
```

- **exit 0** → 出力が本体である。**この周回は、入口と本体を続けて 1 つの手順として読む**
- **それ以外** → `bin/loop-lease release master "<token>"` して終わる。
  **入口だけで進まない**——**手順の大半が無いまま走ると、ゲートも返信も出口も飛ばす**
  （**止まったほうが軽い**）

**読むのは 1.1 のあとである** (#323 のレビュー)。**前に置くと、その周回が始まった時点の
作業ツリーから読む**——**未マージの PR の枝に居た周回は、その PR の本体をそのまま実行する。**
**`bin/loop-procedure-changed` は見つけられない**（**`BEFORE` の側にしか無い変更は
意図して除いてある**。#259）。**`bin/loop-procedure-body` を持たない古い checkout に
居ると、同期の前に読もうとして落ち**、**同期へ到達しないまま毎周回そこで止まる。**

**なぜ分かれているかは `bin/loop-procedure-body` の冒頭にある** (#319)。
**検出はそのまま残す** (#241 / #243)——**入口が変わったときは、これまでどおり鳴る。**

## ステップ 2 以降

**本体にある**（ステップ 1.2 で読んだもの）。**ここには写しを置かない**——
**直す先が 2 つになり、cron が運ぶ本文も元の長さに戻る。**

- **2. open PR を見て、見る順番を決める**
- **3. ゲートを回す** — **マージするか、何が足りないかで分ける**
- **4. 対応を確認し、resolve するか worker へ返す**
- **5. 作業を割って Issue にする**
- **6. 着手順を決める（`ready` を 2 件までに保つ）**
- **7. 空転を検出する**
